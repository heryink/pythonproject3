Projects

3 tiers · every project gets a writeup
Tier 1 · Foundation · Months 1–3
T1 · Month 1
EDA deep-dive on WESAD dataset
You have the data. Distribution analysis, class imbalance, sensor correlation, feature importance. Write it up. Becomes your first technical writeup and a real portfolio piece.
T1 · Month 2
End-to-end classification pipeline
Kaggle/UCI dataset. Clean, engineer features, train multiple classifiers, evaluate with cross-validation + F1. Write up every decision. Teaches the full ML workflow.
T1 · Month 3
Linear + logistic regression from scratch
Pure NumPy. Gradient descent by hand. Then compare to sklearn on the same data. Every mismatch tells you something.
Tier 2 · Build from scratch · Months 3–6
T2 · Month 3–4
Backpropagation engine from scratch
Implement micrograd (scalar autograd). Then extend it. Every DL framework you ever use will make more sense afterward.
T2 · Month 4–5
Character-level language model
Bigram → MLP → full char-LM. Teaches embedding, batching, training loop, evaluation in a context small enough to fully understand.
T2 · Month 5
CNN on CIFAR-10 — train and analyze
Not just accuracy. Visualize filters, plot training curves, analyze failure cases. The analysis is more important than the number.
T2 · Month 6
Transformer attention from scratch
Implement multi-head self-attention in PyTorch without nn.Transformer. Verify against the Vaswani paper. Karpathy + the paper converge here.
Tier 3 · Replication · Months 7+ · highest leverage
T3 · Month 7–onwards
Replicate one paper from scratch
Pick: AlexNet, Word2Vec, DCGAN, DQN, or one from your chosen field. Implement from the paper — no tutorial. Document every gap between paper's claims and what you had to figure out. That gap document IS research thinking. Post it publicly.
Rule for every project
Write up what you tried, what failed, what you changed, what you learned. Three paragraphs minimum. This is how projects become research evidence rather than just code on GitHub.

Paper habit

1 per week · from Month 2 · 3 sentences after every paper
3-pass method
Pass 1: title, abstract, conclusion, figures only (15 min). Pass 2: read everything, skip proofs (1 hr). Pass 3: reconstruct math — only for papers you're replicating.
Months 2–3 · Readable foundations
M2
A Few Useful Things to Know About ML
Domingos, 2012
Best first ML paper. Conceptual, well-written. Builds the right mental model before the math arrives.
M3
Random Forests
Breiman, 2001
Landmark ensemble paper. Read the original alongside CS229's trees module.
M3
XGBoost: A Scalable Tree Boosting System
Chen & Guestrin, 2016
You used this at HealthTrace. Now understand what it's actually doing.
Months 4–5 · Landmark techniques
M4
Dropout: Preventing Neural Networks from Overfitting
Srivastava et al., 2014
Short, clear, important. A simple idea that became ubiquitous.
M4
Adam: A Method for Stochastic Optimization
Kingma & Ba, 2014
You'll use Adam in every project. Read while building training loops.
M5
Batch Normalization
Ioffe & Szegedy, 2015
Short paper, massive impact. Understand why it exists, not just how to use it.
Months 5–6 · Deep learning landmarks
M5
ImageNet Classification with Deep CNNs (AlexNet)
Krizhevsky et al., 2012
The paper that started modern DL. Read during 6.S191's CNN module.
M6
Deep Residual Learning for Image Recognition (ResNet)
He et al., 2015
Skip connections, vanishing gradients. One of the most cited papers in CS.
M6
Attention Is All You Need
Vaswani et al., 2017
Read AFTER Karpathy builds the transformer with you. You'll actually understand it.
Month 7+ · Field exploration
M7
Survey paper in your chosen field
Find via Semantic Scholar · search "[field] survey 2024"
Gives you the map of a field before committing to a specialization course.
M7+
1 current paper/week from NeurIPS / ICML / ICLR
Via Papers With Code · find papers with released code
Read paper → run code → read paper again. The second reading lands differently.
After every paper — write 3 sentences
① What problem they solved. ② What approach they took. ③ What you'd question or extend. The writing is where understanding gets built — not the reading itself.
